# Встроенный TM95STAT.VXD — эксперимент

Это настоящий динамический LE VxD, не переименованный PE и не пустой ресурс.
Исходник `driver/tm95stat.c`, общий протокол `driver/protocol.h` (версия 2),
сборка Open Watcom 2.0. Бинарник включён в EXE как RCDATA/214. `make check`
проверяет точное совпадение ресурса и собранного драйвера.

**Драйвер пока не запускался на Windows 95. Wine VxD не исполняет.**

## Возможности

IOCTL 1 возвращает 24-байтную структуру: size, version, capabilities,
uptime_ms, free_pages, system_pages. Источники — VMM Get_System_Time (0x3f),
_GetFreePageCount (0x5a) и _GetSysPageCount (0x5b). Возможности 1|2 означают
только uptime и счётчики страниц. Число системных страниц не подменяет объём
установленной RAM. Снимок последовательный, а не атомарный между сервисами.

CPU, handles, память/CPU отдельных процессов и сеть этот VxD не измеряет.
Для общего CPU приложение отдельно пробует PerfStats KERNEL\\CPUUsage
через HKEY_DYN_DATA: StartStat, StatData, StopStat. Если данные отсутствуют,
не являются DWORD или выходят за 0–100, отображается Н/Д. Это поведение на
retail Win95/OSR2 ещё требуется проверить, наличие ключа не предполагается.

## Загрузка

Драйвер не загружается автоматически. В Windows 95 выбрать
Параметры → «Экспериментальный VxD». Приложение извлекает свой ресурс
в уникальный временный файл, открывает его через CreateFile/DeviceIoControl,
проверяет длину, версию и capabilities. При закрытии освобождает handle и
пытается удалить файл. Нет изменений SYSTEM.INI, автозагрузки или установки
системной службы. На NT/Wine включение возвращает ERROR_NOT_SUPPORTED до
извлечения файла.

## Что проверить в VMware

Сначала сохранить снимок VM: ошибка ring-0 кода может остановить гостевую ОС.
1. Обычный запуск без драйвера; затем включение. Отказ должен показывать код
   Windows, приложение должно продолжать работать.
2. Uptime растёт; счётчики страниц сопоставимы с диагностикой VMM. Данные
   GlobalMemoryStatus и VMM имеют разные определения и могут различаться.
3. Выключение, повторное включение, закрытие приложения и два экземпляра.
   Временные файлы и загруженный модуль не должны оставаться после закрытия.
4. Неверный IOCTL, нулевые/короткие буферы, неизвестная версия протокола.
   Пока нет проверки из VM, обработка буферов также остаётся непроверенной.
5. Нагрузка CPU и простой: проверить отдельный источник PerfStats.

## Основания ABI и сборки

Структуры и номера сервисов сверялись с открытым проектом
[JHRobotics/vmdisp9x](https://github.com/JHRobotics/vmdisp9x): vmm.h,
vxd_main.c, vxd_lib.c и makefile (MIT, Jaroslav Hensl / JHRobotics).
Исходники драйвера здесь самостоятельные, DDK не включён.

Нормализация LE-объектов (база 0, executable flag) соответствует описанию
[JHRobotics/fixlink](https://github.com/JHRobotics/fixlink), режим -vxd32.
Python-инструмент `tools/fix_vxd.py` реализует эту операцию и проверяет формат.
Open Watcom получен из официального репозитория open-watcom/open-watcom-v2,
Current-build от 1 ноября 2026. Его бинарники не включаются в проект.
