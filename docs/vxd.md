# TM95STAT.VXD — alpha 9, эксперимент для Windows 95 OSR2

**Драйвер ещё не исполнялся в настоящей Windows 95.** Пользовательская система —
4.00.950 B. Сборка, статическая проверка и x86-эмуляция не подтверждают работу
реального загрузчика/VKD/VMM в этой системе.

## Что реализовано

- LE VxD с DDB первым в единственном locked-объекте. DDB вынесен в отдельный
  object-файл, чтобы переменные состояния Watcom не оказались перед ним.
  Проверка сборки отклоняет неверный порядок.
- Загрузка через CreateFile/DeviceIoControl. Временное расширение `.TMP`
  **заменяется** на `.VXD`; раньше получалось длинное имя `.TMP.vxd`.
  GetShortPathNameA преобразует весь путь в DOS 8.3 перед передачей загрузчику.
  Это исправляет проблему формирования пути, но устранение именно наблюдаемой
  ошибки 2 ещё нужно подтвердить на VM.
- При отказе загрузки показывается этап и код Windows. В рабочем каталоге
  создаётся `taskmgr95-vxd.log`: GetVersion, этап, код, имя устройства и размер
  встроенного VxD. Неудачная запись отчёта не меняет исходный код ошибки.
- Время VMM и число свободных/системных страниц.
- Экспериментальный перехват Ctrl+Alt+Del и резидентный режим диспетчера.

**ОЗУ/CPU отдельных процессов, handles и сетевые метрики пока не реализованы.**
Это ещё не VxD «со всеми недостающими фичами». Он не выдаёт оценку размера куч
или EXE за расход ОЗУ и не читает структуры Win98 по непроверенным смещениям
на Win95. Для общего CPU по-прежнему отдельно пробуется PerfStats
`KERNEL\\CPUUsage`; при недоступном источнике — Н/Д.

## Ctrl+Alt+Del

Включение: Параметры → «Заменять Ctrl+Alt+Del (резидентно)». Опция сначала
загружает VxD и включает фильтр, затем записывает только собственное значение
`Taskmgr95.CtrlAltDel` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
Команда автозапуска: полный путь EXE в кавычках с аргументом `/resident`.
Проверять из постоянного каталога приложения, поскольку этот путь сохраняется.
Никакие TASKMAN.EXE, SYSTEM.INI или системные бинарники не заменяются.

- VMM Hook_Device_Service подключает фильтр VKD_Filter_Keyboard_Input
  (`0x000d0012`, CL = scan code). Обработчик находится в locked-коде.
- Обработчик IRQ не выделяет память, не хранит указатели приложения и не
  вызывает USER32. Он увеличивает счётчик; таймер приложения опрашивает VxD
  раз в секунду и восстанавливает/активирует окно.
- Перехваченный make-код Delete превращается в break-код. Переданный ранее
  префикс E0 при этом нормально завершается, без повреждения состояния VKD.
  Учитываются левые/правые Ctrl и Alt, повторы и последовательность Pause.
- Второе отдельное нажатие за две секунды пропускается штатному обработчику.
  Если приложение не обновляло heartbeat более трёх секунд, нажатие также
  пропускается. Это не гарантирует восстановления после зависания самого ядра.
- Heartbeat работает и при паузе счётчиков. Подменой владеет один device handle;
  другой клиент не может её выключить. Закрытие handle снимает перехват.
- Если VMM отказывает в снятии цепочки, драйвер выключает перехват и отклоняет
  динамическую выгрузку, чтобы в цепочке не остался указатель на освобождённый код.

При включённой подмене крестик скрывает окно, процесс продолжает обслуживать
сочетание. Повторный запуск EXE активирует существующее окно. «Файл → Выход»
завершает процесс и снимает перехват; запись автозапуска сохраняется.
Для отключения подмены **и автозапуска** снять ту же опцию в Параметрах.
При отключении самого VxD опция также отключается.

Режим отключён по умолчанию. На NT/Wine включение отклоняется до извлечения
драйвера и изменения автозапуска.

## Протокол 3

IOCTL 1: без входного буфера, выход 32 байта:
`size, version, capabilities, uptime_ms, free_pages, system_pages, cad_events, cad_armed`.
Capabilities: uptime = 1, страницы = 2, возможность включения CAD = 4.
Проверяются версия, длина и необходимые capability-биты.
Число системных страниц не подменяет объём установленной RAM.

IOCTL 2: вход 12 байт `size, version, enable` (0/1), без выходного буфера.
Включение может вернуть ERROR_NOT_SUPPORTED, если VMM не установил фильтр.
Конфликт владельца/невозможность снять фильтр — ERROR_BUSY.
DIOC_OPEN = 0; DIOC_CLOSEHANDLE = 0xffffffff.

## Проверка в VMware

Сначала снимок VM; начать с загрузки без подмены клавиш.

1. Запустить именно alpha 9. Включить «Экспериментальный VxD». Если ошибка
   осталась, сохранить `taskmgr95-vxd.log` и новый текст ошибки с этапом.
2. Если загрузка успешна, проверить uptime/свободные страницы, отключение и
   повторное включение. ОЗУ процессов остаётся Н/Д — эта capability отсутствует.
3. Включить замену Ctrl+Alt+Del. Послать сочетание **через меню VMware**, чтобы
   оно попало гостевой системе. Скрытое/свёрнутое окно должно восстановиться.
4. Проверить отдельное повторное нажатие, NumPad Del, левые/правые модификаторы,
   обычный Delete, Pause и отпускание клавиш. Отключение возвращает штатный диалог.
5. Проверить автозапуск, повторный запуск EXE, крестик, «Файл → Выход» и удаление
   автозапуска через отключение опции. Не удалять EXE до отключения автозапуска.

## Основания ABI и проверки

Структура DDB, DIOC, номера служб VMM и соглашение Hook_Device_Service сверены с
[JHRobotics/vmdisp9x](https://github.com/JHRobotics/vmdisp9x).
ABI фильтра VKD и ordinal 0x12 сверены с VKDPHYS.ASM/VKD.map в
[примере VKD Windows 95](https://github.com/Mike1978uk/win95-intel-inboard-386pc/tree/master/custom_vkd/src).
Сторонний код и DDK в этот проект не включены.

Open Watcom 2 собирает драйвер; `tools/fix_vxd.py` нормализует LE и проверяет DDB.
`make check` сверяет встроенный ресурс с собранным VxD и проверяет чистую логику
клавиатурного фильтра. Дополнительная проверка машинного кода при изменениях VxD:

```sh
# Не входит в обычную проверку и не является зависимостью приложения.
python3 -m pip install unicorn
python3 tests/vxd_emulation.py
```

В эмуляторе исполняется настоящий LE-код, а службы VMM моделируются: DIOC ABI,
проверки буферов, цепочка фильтров, heartbeat, повторное нажатие, владелец и отказ
выгрузки. **Это не выполнение драйвера в Windows 95.**
