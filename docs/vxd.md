# Необязательный VxD: следующий этап

Сейчас драйвера нет. `driver/protocol.h` — проект протокола, а не готовый ABI.
Приложение не устанавливает, не извлекает и не загружает драйвер. CPU отображается
как N/A; график показывает именно загрузку физической памяти.

План: отдельный динамически загружаемый `TM95STAT.VXD`, собранный инструментами
для Windows 95 DDK, и необязательный пользовательский адаптер через
CreateFileA/DeviceIoControl. Поддержка обычного PE EXE компилятором не означает
поддержку сборки VxD: это другой формат (LE), соглашения и сервисы VMM.
Встраивание ресурса с VxD в EXE можно добавить после проверки отдельного драйвера.
Не изменять SYSTEM.INI и не устанавливать автозагрузку ради первого прототипа.

1. Проверить DDK Windows 95: W32_DEVICEIOCONTROL, динамическую загрузку/выгрузку,
   документированные точки учета idle/total и их единицы. Не переносить код NT
   драйверов, GetSystemTimes или случайные адреса структур ядра.
2. Первым сделать handshake с size/version/capabilities. Зарезервированные
   коды открытия/закрытия устройства обрабатывать по контракту DDK.
3. Добавить только чтение общесистемных счетчиков. Снимок атомарный; без
   блокирующей работы, доступа к произвольной памяти или записи по адресу клиента.
   Проверять длины всех буферов. Никаких IOCTL завершения процессов.
4. CPU = 100 * (delta_total - delta_idle) / delta_total. Определить частоту,
   обработку переполнения DWORD, первого снимка, нулевого интервала и перезапуска
   драйвера. Не предполагать существование пригодного счетчика до проверки DDK.
5. При отсутствии драйвера, ошибке версии или неверном снимке оставить CPU N/A.
6. Проверить в VM со снимком диска: загрузку, несколько клиентов, закрытие,
   повторную загрузку, неверные размеры, простой и вычислительную нагрузку.

Базовая цель — retail Windows 95 без обновлений. OSR2 — дополнительная матрица.
Нужен законно предоставленный пользователем установочный носитель и DDK;
в репозиторий их не включать. До этих проверок обещать корректный CPU нельзя.
