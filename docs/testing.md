# Проверки альфы

## Проверено в облачной среде

- Чистая сборка MinGW-w64 GCC 14.2, предупреждения C превращены в ошибки.
- PE-аудит: x86 PE32, OS/subsystem 4.0, только проверенные системные импорты,
  без CRT DLL. Unicode-функции необязательны и вызываются только на NT/Wine.
- LE VxD собирается Open Watcom 2.0; RCDATA/214 точно совпадает с бинарником.
  В alpha 9 проверяются единственный locked-объект и DDB первым в нём.
- Нативная проверка политики Ctrl+Alt+Del: модификаторы, повтор, heartbeat,
  второе нажатие, Pause и переполнение счётчика времени.
- Отдельно при изменении VxD: настоящий LE-код под Unicorn x86 с моделями служб
  VMM — IOCTL/размеры/версии/owner, регистры, цепочка VKD, преобразование Delete,
  heartbeat и отказ выгрузки при неснятой цепочке. Эмулятор VMM не заменяет VM.
- Wine 10.0 WoW64, Xvfb, отдельная **x64 UI-сборка той же кодовой базы**:
  один короткий сценарий, без ошибок. Alpha 9 также проверяет отказ VxD и CAD
  на NT/Wine без загрузки драйвера. Вместо 60 повторов — 6 проходов:
  каждая вкладка в минимальном и большом окне, сохранён контроль отрисовки
  и высоты графиков при 400×450 (64 px).
- В этом же сценарии проверяются значок тестовой программы по цветным пикселям,
  четыре режима просмотра, отключение иконок, диалог столбцов, видимость,
  порядок, ширина, ручное изменение ширины и сохранение после перезапуска.
  Для «Процессов» — имя пользователя собственного тестового процесса по токену,
  видимость/порядок/ширина, сохранение PID выделенной строки при сортировке,
  обновлении и изменении окна; независимое сохранение настроек после перезапуска.
  В alpha 8 в этот же сценарий добавлены перенос шестистолбцового INI alpha 7,
  реальное положительное значение ОЗУ тестового процесса, рост после выделения
  и записи в 16 МиБ, числовая сортировка, изменение ширины/порядка нового столбца
  и сохранение после перезапуска. Сценарий работает во временном каталоге со своим
  INI; отдельный набор тестов памяти не добавлен.
- Wine 10 не поддерживает межпроцессный WM_GETICON и чтение иконок класса
  другого процесса (см. win32u/message.c и class.c в wine-mirror/wine,
  тег wine-10.0). Поэтому под Wine проверен путь извлечения значка из EXE.
  Нативные пути WM_GETICON/класс ещё требуют проверки в Windows 95.
- 29 нативных проверок политики имён процессов: регистр, полный путь, критичные
  Win9x/NT-компоненты, пустое имя, обычные процессы и похожие незащищённые имена.
- Отдельно, при изменениях политики процессов: 10 backend-проверок под Wine64 с контролируемым Tool Help: обычный процесс,
  смена имени при повторном запросе того же PID, защищённый процесс, PID 0,
  собственный PID, отсутствующий PID, отказ снимка/перебора/Tool Help и пустое имя.
  Проверяется реальная функция политики; TerminateProcess тестами не вызывается.
- Скриншот живого окна визуально проверен: страницы/кнопки не перекрываются,
  графики и русские подписи отображаются. Скриншот — Wine64, не Windows 95.

**Непроверено:** выполнение распространяемого x86 EXE, отрисовка на настоящей
Win95 и запуск VxD. Ядро облачной среды не исполняет Linux i386; Wine WoW64
падает при входе в compat32 даже с минимальным независимым MessageBox.
Попытки Wine32 через QEMU и WoW64 через QEMU тоже не дали работоспособного
32-битного запуска. Это ограничение тестовой среды, не успешный тест x86 EXE.

Тест внешний: `tests/gui_smoke.c`. Он находит созданное им окно по PID,
использует реальные сообщения контролов, не содержит hook-кода в приложении.
Для снимков `TM95_CAPTURE_HOLD=1` удерживает окно 10 секунд после проверок.
Wine64-сборка не должна попадать в dist или выдаваться за Win95-версию.

## Приёмка в Windows 95 / VMware

Проверить retail Win95, затем OSR2, 640x480, штатные COMCTL32, без KernelEx.
Сначала использовать снимок диска и запускать приложение без VxD.
Для alpha 9 начать с пользовательской 4.00.950 B и шагов в [vxd.md](vxd.md).

- Запуск EXE: нет ошибок DLL/импортов. Все три вкладки переключаются.
- Развернуть, восстановить, уменьшить окно до 400×450; закрыть его другим окном и снова
  открыть. Через несколько отсчётов скрытые списки не появляются на Performance.
- Applications/Processes: белый фон списков, кнопки целиком видны и перерисовываются,
  переключение на Performance скрывает их. Графики не мерцают и не оставляют следов.
- New Task: notepad.exe, команда с путём в кавычках, неверная команда.
  End Task должен отправить обычное закрытие, позволяя сохранить документ.
- Приложения: значок Notepad отображается; «Вид» переключает четыре режима.
  В диалоге столбцов включить PID/класс/программу, изменить порядок и ширину.
  Обновление, смена языка и перезапуск сохраняют настройки. Размер столбца,
  изменённый мышью, не сбрасывается при изменении размера окна.
- Столбец «ОЗУ (КБ)» на Win95 пока показывает Н/Д, включая режим с текущим VxD.
  Приложение запускается без PSAPI.DLL и новых NT-импортов. Столбец можно скрыть,
  переместить и изменить его ширину; старый порядок alpha 7 сохраняется.
  Это ограничение источника, не проверка настоящего расхода ОЗУ на Win95.
- Процессы: «Вид → Настроить столбцы» — скрыть путь, переместить «Пользователь»,
  задать ширину, проверить после обновления/смены языка/перезапуска. Имя образа
  остаётся первым. Выделение после сортировки по PID относится к тому же процессу.
  На Win95 «Пользователь» — общее имя текущего сеанса для всех строк, а при
  недоступном имени — Н/Д. Это декоративная подпись, не отдельные владельцы.
- PID Notepad (если включён соответствующий столбец) совпадает между вкладками; приоритет Idle → Normal работает.
  End Process: No сохраняет процесс, Yes завершает; свой PID защищён.
  Выбор KERNEL32.DLL, MSGSRV32.EXE, MPREXE.EXE отключает завершение.
  Обработчик команды также должен отклонять защищённый PID.
- При 400×450 все панели Performance видны без прокрутки при штатном шрифте.
  Значения не накладываются на подписи. В большом окне возвращаются полные
  заголовки; кнопки и список приложений сохраняют корректные размеры.
- Русский ↔ English: меню, кнопки, заголовки списков, панели, сообщения.
  Для Win95 нужен ACP 1251. Перезапуск сохраняет язык при доступной записи INI.
- Pause останавливает отсчёты, Refresh Now добавляет отсчёт, выделение сохраняется.
- Память сверить с диагностикой ОС. Ресурс подкачки не называть NT commit charge.
  Общий CPU должен реагировать на нагрузку либо оставаться Н/Д при отказе источника.
- About/Run должны открываться через Shell32, диалоги должны нормально закрываться.
- VxD проверять отдельно по [vxd.md](vxd.md), начиная со снимка VM.

Не подтверждены отсутствие GDI-утечек при многочасовой работе и глубокая
диагностика зависаний. Нужны длительный прогон и реальная Win95.

Источник метрики на NT/Wine: [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo),
поле [WorkingSetSize](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters).
GetProcessWorkingSetSize возвращает ограничения, а не текущий объём, и здесь не используется.
