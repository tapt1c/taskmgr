# Task Manager 95

Нативный диспетчер задач для Windows 95 с интерфейсом по мотивам классического
диспетчера Windows XP. Первый прототип на C89 / ANSI Win32, без сторонних
библиотек и DLL C runtime. Совместимость с настоящей Windows 95 **пока не проверена**.

## Скачать прототип

Готовый [taskmgr95.exe](dist/taskmgr95.exe) и [SHA-256](dist/SHA256SUMS)
находятся в `dist`. В GitHub откройте EXE и нажмите **Download raw file**.
Это экспериментальная сборка из коммита `d9e7954`: кросс-сборка и аудит PE
пройдены, запуск на Windows 95 еще не проверен. VxD в сборку не входит.

## Что реализовано

- Applications: видимые верхнеуровневые окна, PID, переключение и запрос закрытия.
- Processes: Tool Help, PID, потоки, базовый приоритет, имя/путь как его вернула ОС.
- Принудительное завершение с подтверждением; свой PID и PID 0 исключены.
- Изменение класса приоритета: Idle, Normal, High (с подтверждением).
- Performance: GlobalMemoryStatus и история загрузки физической памяти за
  последние 120 отсчетов; один отсчет в секунду при включенном обновлении.
- New Task: CreateProcessA; Always on Top, пауза и ручное обновление.
- Сохранение выделенной строки при обновлении; ошибки API показываются пользователю.

CPU и память отдельного процесса, сеть, иконки приложений, сортировка и VxD
пока не реализованы. Неизвестные показатели не заменяются фиктивными нулями.
У Windows 95 нет пользовательских сеансов в смысле XP — вкладки Users нет.
Закрытие приложения отправляет WM_CLOSE, а не принудительно убивает его.
Полноценная диагностика зависаний и учет 16-битных задач — отдельная работа.

## Сборка в Linux

Нужны GNU make, Python 3 и i686 MinGW-w64 GCC/binutils. В Debian/Ubuntu пакеты:
`gcc-mingw-w64-i686`, `binutils-mingw-w64-i686`.

```sh
make
make check
```

Результат: `build/taskmgr95.exe`. Скопировать один EXE в гостевую систему.
Нужны штатные KERNEL32, USER32, GDI32 и COMCTL32 Windows 95.
Нет Unicode API, зависимости от MSVCRT, manifest или современных расширений
ListView. Линкер выставляет x86 PE32 и OS/subsystem 4.0; аудит импортов защищает
от случайного добавления новых DLL/API. Это необходимые, но недостаточные
условия совместимости. Современный MinGW здесь используется без его CRT startup.

Если компилятор установлен отдельно, передать `CROSS=/path/to/i686-w64-mingw32-`.
В этой облачной среде локальная установка находится в
`/workspace/toolchains/mingw/root/usr/bin`; добавить ее в PATH и использовать
`CROSS=i686-w64-mingw32- CC=i686-w64-mingw32-gcc-win32` при необходимости.

## Проверка на Windows 95

См. [ручную проверку](docs/testing.md) и [план VxD](docs/vxd.md).
Успешная кросс-сборка и проверка импортов не являются проверкой выполнения.
Современная Windows/Wine полезны для проверки UI, но не заменяют Windows 95.

Файлы установки ОС, DDK и драйверы из других проектов не включены.
