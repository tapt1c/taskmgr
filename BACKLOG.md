# Задачи Task Manager 95

Актуально для **alpha 12 / 0.1.12**, коммит
[`61c9174`](https://github.com/tapt1c/taskmgr/commit/61c9174358b1932d8dfcc630361c1ee5887efa16).
`[x]` означает выполненный указанный этап; проверка в настоящей Win95 отмечается
отдельно. Этот список не означает, что все задачи нужно выполнять за один запрос.

## P0 — загрузка VxD на Windows 95 OSR2

Целевая пользовательская VM: VMware, Windows 95 **4.00.950 B**, без DDK.
Последний полученный журнал относится к **alpha 11**:

| Наблюдение | Результат |
| --- | --- |
| Обычное чтение TM95STAT.VXD | Все 1557 байт совпадают с ресурсом |
| Открытие по полному пути / только имени | Ошибка 2 в обоих случаях |
| Открытие системного VWIN32 | Успешно |
| Минимальный TM95TEST.VXD | Все 631 байт прочитаны, открытие — ошибка 2 |
| Запрос к контрольному VxD | Не выполнялся (`Probe query attempted: 0`) |

Отказ происходит до IOCTL. Журнал сужает поиск к динамической загрузке/формату
образа; он не доказывает конкретную причину отказа загрузчика.

- [x] Исправить имена и короткий путь, добавить побайтное чтение, запасную форму
  открытия, очистку временных файлов и журнал этапов/ошибок.
- [x] Добавить независимую проверку VWIN32 и минимальный встроенный TM95TEST.
- [x] В alpha 12 исправить оставленный Watcom нулевой preload и перепаковать LE:
  страницы 512 байт, выравнивание данных 4096, LCOD, прямой экспорт DDB,
  без IOPL и OS/2 autodata; пересобрать таблицы страниц и перемещений.
  Структура сверена с готовым WinIo 2.0 для Win95, код основного VxD сохранён.
- [x] Проверить ресурсы, отбраковку старого образа, идемпотентность упаковки,
  x86-эмуляцию обоих VxD и существующий Wine-сценарий (67 проверок без ошибок).
- [ ] Получить результат **alpha 12 после перезагрузки VM**: включение
  «Экспериментального VxD», при отказе — новый `taskmgr95-vxd.log`.
- [ ] Если отказ сохраняется, сравнить основной и контрольный драйверы по новому
  журналу и исследовать загрузчик Win95. Не считать очередное изменение заголовка
  доказанным исправлением без результата настоящего VMM.
- [ ] Подтвердить успешную загрузку, корректный ответ протокола 3, uptime и
  свободные страницы; затем отключение и повторное включение без зависаний.

Критерий закрытия P0: настоящий Win95 открывает устройство и получает корректный
ответ; отключение/повторное включение работают. См. [подробности VxD](docs/vxd.md).

## P1 — недостающие метрики Win95

Эти источники **пока не реализованы**, даже при включённом текущем VxD.

- [ ] Найти и подтвердить источник ОЗУ отдельного процесса для Win95 OSR2.
  Определить, что именно измеряется и как учитываются разделяемые страницы.
  Проверить на процессе с известным выделением/освобождением памяти и при его
  завершении; не подставлять сумму куч или размер EXE.
- [ ] Реализовать источник CPU отдельного процесса с определённым интервалом
  измерения; проверить простой, нагрузку, завершение процесса и повторное
  использование PID.
- [ ] Определить доступность и смысл счётчика handles на Win95, затем реализовать
  получение, если источник подтверждён. Не смешивать его с NT handles или
  процентами свободных USER/GDI-ресурсов.
- [ ] Определить конкретные сетевые показатели и доступный на Win95 источник
  перед реализацией; не обещать счётчики отдельных процессов без основания.
- [ ] Для подтверждённых источников расширить capability-биты/протокол и клиент,
  сохранив Н/Д при недоступности данных и явный отказ несовместимой версии.

Сейчас общий CPU пробуется через PerfStats `KERNEL\CPUUsage`; при недоступности —
Н/Д. На NT/Wine ОЗУ процесса уже берётся из WorkingSetSize. Это не подтверждение
наличия соответствующей метрики на Win95.

## P1 — Ctrl+Alt+Del в настоящей Win95

- [x] Реализовать экспериментальный фильтр VKD, владение handle, heartbeat,
  пропуск второго отдельного нажатия и снятие цепочки перед выгрузкой.
- [x] Добавить резидентный режим, восстановление окна, собственный HKCU Run
  и отключение автозапуска через опцию. На NT/Wine включение отклоняется.
- [ ] После закрытия P0 проверить в VM отправку сочетания через меню VMware,
  восстановление скрытого/свёрнутого окна и работу при паузе счётчиков.
- [ ] Проверить левые/правые Ctrl и Alt, NumPad Del, повторы, Pause, отпускание
  клавиш, обычный Delete и второе отдельное нажатие.
- [ ] Подтвердить поведение при потере heartbeat, закрытии владельца,
  отключении опции, «Файл → Выход» и перезагрузке с автозапуском.

Режим остаётся экспериментальным и выключенным по умолчанию до подтверждения
на реальной системе. Полный сценарий — в [docs/vxd.md](docs/vxd.md).

## P2 — интерфейс и совместимость

- [x] Окно 400×450, плотные нижние блоки, компактные подписи и графики.
  В Wine64 минимальная высота графиков истории — 64 пикселя.
- [x] Иконки приложений, четыре режима просмотра, настройка видимости, порядка
  и ширины столбцов обеих вкладок, сортировка и сохранение INI.
- [x] Столбцы «Пользователь» и «ОЗУ (КБ)». На Win95 имя пользователя декоративное,
  ОЗУ — Н/Д; на NT данные берутся из токена и WorkingSetSize соответственно.
- [x] Защита критичных процессов, PID 0 и самого диспетчера с повторной проверкой
  непосредственно перед завершением, включая End Task для защищённых процессов.
- [ ] Пройти оставшуюся ручную приёмку Win95 OSR2: минимальное окно, панели,
  иконки через WM_GETICON/класс, столбцы, сортировка, INI и диалоги Shell32.
- [ ] Проверить обе локализации на Win95 с ACP 1251 и штатными шрифтами/COMCTL32;
  затем совместимость с retail Win95 по [docs/testing.md](docs/testing.md).
- [ ] Проверить длительную работу и обновление списков на утечки GDI/USER
  и устойчивость к зависшим/исчезающим окнам.

не запускать заново сборку, Wine и эмулятор. Правила работы — в [AGENTS.md](AGENTS.md).
